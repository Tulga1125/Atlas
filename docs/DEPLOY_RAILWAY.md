# Deploying Atlas on Railway

Atlas runs at **https://atlas.tagent.space** in its own Railway project, `atlas` (workspace "Tulga Enkhbold's Projects"), separate from the `fitness` project so it cannot disturb the other tagent.space services. Supabase is self-hosted in the same project.

## Services

| Service | Source | What it does |
|---|---|---|
| `db` | `deploy/db/Dockerfile` (`supabase/postgres:17.6.1.136`) | Postgres with Supabase's roles and extensions. Volume at `/data` holds the data directory and the key directory. Private only. |
| `auth` | image `supabase/gotrue:v2.197.0` | Supabase Auth (magic links). Signup disabled. Private only. |
| `rest` | image `postgrest/postgrest:v14.18` | The database API with row-level security. Private only. |
| `gateway` | `deploy/gateway/Dockerfile` (Caddy) | Public Supabase URL: `/auth/v1` → `auth`, `/rest/v1` → `rest`. Railway domain `gateway-production-8885e347.up.railway.app`. |
| `migrate` | `deploy/migrate/Dockerfile` | One-shot job: applies `supabase/migrations` in order, recorded in `supabase_migrations.schema_migrations`. Never restarts. Runs again on every deploy and skips applied versions. |
| `web` | repo root (Railpack, Node 24, pnpm) | The Next.js app. Custom domain `atlas.tagent.space`. |

All services deploy from branch `feature/youtube-intelligence` until it is merged; then switch each to `main` in the service settings.

## Secrets

Generated once and stored as Railway **shared variables**: `POSTGRES_PASSWORD`, `JWT_SECRET`, `ANON_KEY`, `SERVICE_ROLE_KEY`, `CRON_SECRET`. Services refer to them as `${{shared.NAME}}`; nothing is in the repository. `ANON_KEY` and `SERVICE_ROLE_KEY` are HS256 JWTs signed with `JWT_SECRET` (roles `anon` and `service_role`). Rotating `JWT_SECRET` means re-signing both keys.

Set by the owner in the `web` service:

- `YOUTUBE_API_KEY`: needed for YouTube discovery and manual video entry.
- `APPLE_MUSIC_DEVELOPER_TOKEN`: when obtained. Then change `ATLAS_ENV` from `staging` to `production`, which turns on the strict start-up check in `src/lib/production-env.ts`.
- `ANTHROPIC_API_KEY`: for later phases (tag suggestions, sentiment).

## Current address (until the domain is connected)

The site runs at **https://web-production-a6a79d12.up.railway.app**. For now `NEXT_PUBLIC_SITE_URL` (web), `GOTRUE_SITE_URL` (auth) and `ALLOWED_ORIGIN` (gateway) point there; `GOTRUE_URI_ALLOW_LIST` allows both addresses. When connecting `atlas.tagent.space`, set those three back to `https://atlas.tagent.space` and redeploy `web` (the site URL is built into the page bundle).

## Deploying changes

Railway's API token cannot create GitHub auto-deploy triggers for this repo ("no one in the project has access to it"), so pushes do not deploy by themselves and a plain redeploy builds `main`. Until fixed, deploy a change by pinning the commit (`serviceInstanceDeployV2` with `commitSha`). To fix: in the Railway dashboard, for `db`, `gateway`, `migrate` and `web`, open Settings → Source, make sure Railway's GitHub app can see `Tulga1125/atlas`, and set the branch (`main` after merging).

## DNS

`tagent.space` is on Cloudflare. Add **CNAME `atlas` → `sqqd8twa.up.railway.app`**, proxied, SSL mode *Full*, like the other tagent.space services. Railway issues the certificate once the record resolves.

## Email (needed for staff sign-in)

Staff sign in with a magic link, so Auth needs SMTP. Set on `auth`: `GOTRUE_SMTP_HOST`, `GOTRUE_SMTP_PORT`, `GOTRUE_SMTP_USER`, `GOTRUE_SMTP_PASS`, `GOTRUE_SMTP_ADMIN_EMAIL`, `GOTRUE_SMTP_SENDER_NAME`. Until then, an administrator account can be created with the Auth admin API and signed in with a one-time link generated by the same API (`POST /auth/v1/admin/generate_link` with the service role key).

## Scheduler (installed by the migrate job)

The `migrate` job installs `supabase/operations/install-youtube-schedule.sql` when its variable `ATLAS_SCHEDULE` is `youtube` or `all`, using `ATLAS_SITE_URL` and `CRON_SECRET` (`${{shared.CRON_SECRET}}`) from its own variables; it stores both in Vault and never prints them. Jobs (UTC): queue worker every minute, YouTube retention 21:00, discovery 21:15, statistics 21:30, channel statistics 21:35, and with `all` the Apple Music chart at 22:00 (05:00–06:00 in Ulaanbaatar). Since 2026-11-17 it is `all`. When the domain moves to `atlas.tagent.space`, change `ATLAS_SITE_URL` and redeploy `migrate`.

## Apple Music token

`APPLE_MUSIC_DEVELOPER_TOKEN` on `web` is an ES256 developer token signed with the owner's MusicKit key (Key ID `6DK9T2482J`, Team ID `7H62LULA36`; the `.p8` file is never committed). Apple allows at most six months: the current token **expires on 2027-05-18**. Before then, sign a new one with the same key (header `{"alg":"ES256","kid":"6DK9T2482J"}`, claims `iss` = Team ID, `iat`, `exp` ≤ 15,777,000 s later) and replace the variable. `ATLAS_ENV` is still `staging`; switching to `production` turns on the strict start-up check in `src/lib/production-env.ts`, which warns as the expiry approaches.

## Backups

The `db` volume is the only copy of the data. Before relying on it, enable Railway volume backups for `db` or schedule a `pg_dump` elsewhere, and rehearse a restore as `docs/PRODUCTION_READINESS.md` requires.
